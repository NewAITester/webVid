# ابزارهای اختیاری و آپدیت کم‌حجم

## رفتار کاربر

- هیچ هسته یا کتابخانه‌ای در شروع برنامه یا صرفاً باز کردن مدیر ابزارها دانلود نمی‌شود.
- «↓ ابزارها» در کتابخانه و ویرایشگر و «مدیریت دانلود FFmpeg» در پنل تبدیل موجود است.
- کاربر ابزارها را انتخاب می‌کند و قبل از دانلود حجم دقیق فایل‌های جدید **با وابستگی‌ها** را تأیید می‌کند.
- هنگام دانلود، نام ابزار/فایل، حجم دریافت‌شده و کل، نوار پیشرفت و مرحلهٔ بررسی سلامت دیده می‌شود.
- دانلود ترتیبی در Worker مستقل انجام می‌شود؛ رابط اصلی کار سنگین جمع‌آوری فایل/هش را انجام نمی‌دهد.
- لغو و قطع اتصال فایل‌های کامل را نگه می‌دارد؛ فایل نیمه‌کاره نصب نمی‌شود. ادامهٔ بایت‌به‌بایت فایل نیمه‌کاره پیاده نشده است.
- هستهٔ پایتون برای پل فعلی به numpy نیاز دارد؛ کتابخانه‌های دیگر جداگانه قابل انتخاب‌اند.
- در صورت نبود پایتون، مفسر داخلی موجود باقی می‌ماند (هم‌ارز CPython و همهٔ کتابخانه‌ها نیست).
- FFmpeg بدون نصب ابزار، دانلود مخفی از CDN ندارد؛ کاربر به مدیر ابزارها هدایت می‌شود.

## ماندگاری و امنیت

`wv-tools-sha256-v1` یک Cache Storage مستقل از نسخهٔ اپ است. کلید فایل، هش SHA-256
محتوای آن است؛ فایل‌های یکسان در نسخه‌های بعدی دوباره دانلود نمی‌شوند. هسته و wheelها
نسخه و URL ثابت، اندازه و هش دارند. فایل خراب/ناقص قبل از ذخیره رد می‌شود.
Service Worker فقط فایل‌های تأییدشده را از آدرس‌های هم‌مبدأ `runtime/…` ارائه می‌کند؛
فایل مفقود را هرگز خودکار از اینترنت نمی‌گیرد. مسیر نصب وب در زیرپوشه هم پشتیبانی می‌شود.

درخواست `navigator.storage.persist()` بهترین تلاش است، نه تضمین: مرورگر می‌تواند رد کند.
حذف اپ، پاک کردن داده‌های اپ/سایت یا فشار حافظه و پاک‌سازی مرورگر ممکن است ابزارها را حذف کند.
تغییر `appId`، مبدأ وب یا scheme نیز حافظه را عوض می‌کند. در WebView بدون Service Worker /
Cache Storage / secure context پیام روشن نمایش داده می‌شود، نه دانلود مکرر یا هنگ خاموش.

### امضای APK — شرط ضروری آپدیت بدون حذف داده

APK جدید باید همان application ID و **همان کلید امضای نسخهٔ نصب‌شده** را داشته باشد.
ورک‌فلوی موجود `assembleDebug` استفاده می‌کند و این تغییر کلید امضا را مدیریت نمی‌کند.
ساخت debug روی runner تازه ممکن است کلید تازه بسازد؛ چنین APKای آپدیت قابل‌نصب نسخهٔ قبلی نیست.
از keystore پایدار و امن در CI استفاده کنید. keystore را در Git یا فایل‌های عمومی نگذارید.
کلید قبلی را با کلید تازه جایگزین نکنید؛ اگر نسخهٔ نصب‌شده با کلید دیگری امضا شده،
مهاجرت امضا/داده یک کار جداست. حذف و نصب مجدد برای دور زدن ناسازگاری امضا، کش ابزارها را حذف می‌کند.

## بیلد

`prepare-tools.mjs` جایگزین فراخوانی دو اسکریپت قدیمی copy-ffmpeg/copy-pyodide در prebuild است.
نسخهٔ npm Pyodide برای هسته استفاده می‌شود. برای wheelها، در lock قدیمی `info.version`
و در قالب جدید ABI بدون این فیلد، نسخهٔ ثابت بستهٔ npm (مانند `314.0.7`) استفاده می‌شود. متادیتای PyPI نسخهٔ ثابت و HEAD اندازهٔ فایل‌ها در CI خوانده می‌شود؛
خود wheelها دانلود یا داخل APK قرار داده نمی‌شوند. نبود متادیتای لازم، بیلد را متوقف می‌کند.
فونت‌ها و رسانه‌های نمونه همچنان مثل قبل همراه اپ هستند.

## اصلاحات اتصال/عملکرد در این محدوده

- دانلود و SHA-256 در Worker، دانلود ترتیبی، به‌روزرسانی محدودشدهٔ پیشرفت و بررسی فضای آزاد.
- جلوگیری از دانلود هم‌زمان تکراری و اجرای هم‌زمان روی یک نمونهٔ FFmpeg.
- آزادسازی فایل‌ها/رویدادهای FFmpeg و پاکسازی تایمر و URL بررسی مدت رسانه.
- محدود کردن به‌روزرسانی گزارش FFmpeg به یک بار در ۱۲۰ میلی‌ثانیه.
- جلوگیری از جایگزینی کنترل‌های لغو/پیشرفت پنل در وسط اجرا و نادیده گرفتن render قدیمی.
- شکست بارگذاری Python/package دیگر به‌عنوان «نصب موفق» علامت‌گذاری نمی‌شود؛ پس از نصب ابزار قابل بازیابی است.

**محدودیت:** اجرای کد پایتون و پل cairo موجود هنوز روی thread اصلی‌اند؛ این تغییر همهٔ
لگ‌های محاسباتی پروژه‌های سنگین را برطرف نمی‌کند. جداسازی کامل renderer Python به Worker
نیازمند بازطراحی پل cairo و زمان‌بندی فریم‌هاست و در این تغییر انجام نشده است.

## تست و معیار پذیرش

- `node tests/tools.test.mjs`: برنامه‌ریزی وابستگی، کش ثابت، بررسی هش/حجم، لغو، خرابی، حفظ فایل کامل و مسیر SW.
- `npm run test:tools-browser`: Chromium با فایل آزمایشی کوچک؛ تأیید اختیاری UI، دانلود Worker، import از SW، reload، آفلاین و تلاش مجدد.
- برای تست مرورگر، Playwright و Chromium نصب‌شده لازم‌اند؛ `CHROMIUM_PATH` مسیر مرورگر موجود را انتخاب می‌کند.

تست‌های محلی با فایل آزمایشی انجام شده‌اند، **نه wheel واقعی یا APK**. پیش از ادغام:

1. CI بیلد کامل را با Pyodide واقعی نصب‌شده اجرا کند؛ manifest حجم/هش معتبر تولید کند و APK بدون wasm/wheel ابزارها باشد.
2. روی APK واقعی، Service Worker و ارائهٔ module/wasm از کش در WebView تأیید شود.
3. Python + numpy، یک کتابخانهٔ Pyodide، یک wheel پایتون خالص و FFmpeg واقعاً نصب و اجرا شوند.
4. پس از بستن/باز کردن، حالت هواپیما و نصب آپدیت **هم‌امضا بدون uninstall**، بدون دانلود دوباره اجرا شوند.
5. لغو، اینترنت ضعیف، کمبود فضا و تغییر نسخهٔ یک ابزار روی گوشی کم‌حافظه بررسی شوند.
6. تا عبور از موارد بالا تغییر را آزمایشی نگه دارید؛ تست Chromium جای تست APK را نمی‌گیرد.


## اصلاح مسیر Service Worker در APK

در Capacitor، `https://localhost` یک مبدأ مجازی برای assets است، نه سرور HTTPS واقعی.
درخواست‌های Service Worker از WebViewClient معمول صفحه عبور نمی‌کنند. بنابراین وجود
`tools-sw.js` در APK به‌تنهایی برای ثبت worker کافی نبود؛ خطای «unknown error … fetching
script» قبل از شروع هر دانلود رخ می‌داد.

`ToolServiceWorkerPlugin` هنگام ثبت افزونه‌ها و **قبل از بارگذاری اولین صفحه**، با
`ToolServiceWorkerBridge` یک `ServiceWorkerClientCompat` نصب می‌کند
و فقط GETهای **همان مبدأ داخلی اپ** را به `WebViewLocalServer` خود Capacitor می‌فرستد.
CDN و مبدأهای دیگر دست‌نخورده می‌مانند. TLS، CORS، scheme و appId تغییری نمی‌کنند.
تمام assets داخلی پوشش داده می‌شوند تا reload صفحهٔ کنترل‌شده و دریافت manifest داخل
worker هم کار کند؛ Activity از طریق WeakReference نگهداری می‌شود تا نشت حافظه ایجاد نشود.

فهرست ابزارها اکنون قبل از اتصال worker نمایش داده می‌شود؛ خطای اتصال فهرست را خالی
نمی‌کند، دانلود تا آماده شدن اتصال غیرفعال می‌ماند و دکمهٔ تلاش دوباره موجود است.

تست‌های اضافه:
- `cd android && ./gradlew testDebugUnitTest`: سیاست محدودکردن درخواست به مبدأ داخلی.
- `cd android && ./gradlew connectedDebugAndroidTest`: ثبت worker از assets واقعی APK،
  خواندن manifest و پاسخ مسیر runtime در WebView گوشی/شبیه‌ساز (بدون دانلود ابزار واقعی).
  تست دوم به گوشی/شبیه‌ساز متصل نیاز دارد؛ تست مرورگر جایگزین آن نیست.

برای این اصلاح باید **APK جدید** ساخته و نصب شود؛ تغییر فایل‌های وب به‌تنهایی اتصال
Native را اضافه نمی‌کند. برای امتحان کردن، داده‌ها یا برنامهٔ قبلی را حذف نکنید؛ APK
هم‌امضا نصب کنید. موفقیت تست Android و دانلود واقعی را بدون اجرای آن‌ها تأییدشده فرض نکنید.

CI شاخهٔ `feature/optional-runtime-downloads` علاوه بر ساخت APK، تست WebView را روی
شبیه‌ساز Android 30 اجرا می‌کند و گزارش را در artifact `android-tool-tests` قرار می‌دهد.
در اجرای دستی workflow، گزینهٔ `test_webview` برای شاخه‌های دیگر هم این تست را فعال می‌کند.
شکست تست WebView انتشار artifact APK آن اجرا را متوقف می‌کند.
