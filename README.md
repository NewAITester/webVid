## اجرا

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # خروجی در dist/

npm test                       # همهٔ تست‌های منطق (موتور، آهنگ، موشن، FFmpeg)

# تست‌های تصویری (یک‌بار نصب مرورگر لازم است)
npx playwright install chromium
node tests/shot.mjs 16.8 44.9  # اسکرین‌شات در لحظه‌های دلخواه
node tests/dbg.mjs             # وضعیت داخلی موتور در یک لحظه
```

## انتشار

ورک‌فلو `.github/workflows/web.yml` در هر پوش به `main` بیلد می‌گیرد،
تست‌ها را اجرا می‌کند و خروجی را به‌عنوان artifact می‌گذارد.

برای داشتن آدرس زنده:
۱. ریپو را **public** کنید (روی پلن رایگان، Pages فقط برای ریپوی عمومی کار می‌کند)
۲. Settings ← Pages ← Source: **GitHub Actions**

مسیرها نسبی‌اند (`base: './'`)، پس هم روی زیرمسیر `/webVid/` درست کار
می‌کنند و هم بعداً داخل WebView که از `file://` لود می‌شود.

## معماری

**قانون طلایی:** `renderFrame(t)` یک **تابع خالص** است. برای یک زمان
مشخص همیشه دقیقاً همان تصویر را می‌کشد، مستقل از فریم‌های قبلی.

به‌خاطر همین قانون می‌شود تایم‌لاین را آزادانه اسکراب کرد، از وسط
کلیپ پیش‌نمایش گرفت، رندر را موازی کرد، و از هر بخش تصویر کوچک ساخت.

نتیجهٔ عملی: هیچ‌جا `Math.random` استفاده نمی‌شود — به‌جایش `hash(n)`
که با ورودی یکسان همیشه خروجی یکسان می‌دهد.

### استودیوی موشن در یک نگاه

هر لایه یک شیء JSON ساده است:

```js
{ id, type: 'shape', name, t0: 2, t1: 6, blend: 'screen', parent: null, clip: 'none',
  props: { x: { v: 0, k: [{ t: 0, v: -300, e: 'outBack' }, { t: 1, v: 0 }] },   // کی‌فریم
           rot: { v: 0, x: 'loop(2) * 180' } },                                  // عبارت
  effects: [{ type: 'glow', on: true, p: { r: { v: 20 } } }],
  anim: { in: { id: 'pop', dur: 0.4 }, out: { id: 'fade' }, loop: { id: 'none' } } }
```

`evalLayer(L, t)` همه را به یک ماتریس و چند عدد تبدیل می‌کند و `MotionRenderer`
آن را می‌کشد؛ پس پیش‌نمایش و خروجی دقیقاً یکی‌اند (قانون طلایی).

### افزودن افکت تازه به لایه‌ها

در `src/motion/schema.js` یک مورد به `EFFECTS` اضافه کنید (پارامترها خودکار در پنل
ظاهر و کی‌فریم‌پذیر می‌شوند) و در `src/motion/render.js` نحوهٔ اعمالش را بنویسید.

### FFmpeg

پایتون واقعی، کتابخانه‌های آن و هستهٔ FFmpeg **داخل APK بسته‌بندی نمی‌شوند**.
از دکمهٔ «↓ ابزارها» در صفحهٔ پروژه‌ها یا ویرایشگر، ابزارهای دلخواه را انتخاب کنید.
نام، نسخه، حجم هر ابزار، حجم کل با وابستگی‌ها و پیشرفت فایل جاری نمایش داده می‌شود؛
دانلود فقط با تأیید کاربر شروع می‌شود. پس از نصب، پردازش روی خود دستگاه و آفلاین است.

فایل‌های کامل با SHA-256 بررسی و در حافظهٔ مستقل از بیلد ذخیره می‌شوند. آپدیت معمولی
برنامه فایل یکسان را دوباره دانلود نمی‌کند؛ فقط فایل‌های جدید یا حذف‌شده لازم خواهند بود.
پاک کردن داده‌ها، حذف برنامه یا پاک‌سازی مرورگر این حافظه را هم می‌تواند حذف کند.

`npm run build` فقط فهرست کوچک ابزارها را تولید می‌کند (برای متادیتای PyPI و حجم‌ها
اتصال اینترنت در محیط بیلد لازم است، نه دانلود همهٔ wheelها). قبل از `npm run dev`
یک بار `node scripts/prepare-tools.mjs` را اجرا کنید.

جزئیات فنی، شرایط آپدیت APK و چک‌لیست تست در [docs/optional-tools.md](docs/optional-tools.md) است.

## چرا وب و نه اندروید نیتیو

مرورگر موبایل همهٔ چیزهای سخت را از قبل دارد: شکل‌دهی فارسی
(HarfBuzz + ICU)، رسم روی GPU (Skia)، و انکود سخت‌افزاری (WebCodecs).
نسخهٔ نهایی داخل WebView بسته‌بندی می‌شود و یک اپ اندروید واقعی
و آفلاین می‌شود.‌‌ ‌‌ ‌‌‌‌‌
